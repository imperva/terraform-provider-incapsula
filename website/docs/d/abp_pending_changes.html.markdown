# incapsula_abp_pending_changes

Produces a marker value used to trigger a new `incapsula_abp_preflight` (and thereby a new publish) when the ABP configuration changes.

**How it actually works.** This data source performs no API call and does not inspect the account: `hash` is a fixed value. Change detection comes entirely from `depends_on`. When something this data source depends on has a planned change, Terraform postpones reading it, `hash` becomes unknown for the duration of the plan, and the preflight that consumes it is therefore replaced. When nothing in `depends_on` changes, `hash` stays the same and no new preflight is created.

Two consequences worth knowing. **Every ABP resource must be reachable through `depends_on`** (for example by keeping them all in one module and depending on that module): a change to a resource outside it does not trigger a preflight or a publish, so it stays pending — `terraform plan` reports no changes while the account still has unpublished changes — until something else publishes the account, which then activates it along with everything else. And **changes made outside Terraform are never noticed**, so they do not trigger a publish either.

## Example Usage

```terraform
# Produces a marker that changes whenever Terraform has a planned change inside
# `depends_on`, which is what makes `incapsula_abp_preflight` take a fresh
# snapshot. List every ABP resource here (most simply: the module that holds
# them) — a change outside `depends_on` does not trigger a publish.
data "incapsula_abp_pending_changes" "current" {
  depends_on = [module.abp]
}
```
